# Self-service account data exports

This bounded privacy feature adds human-session routes: `POST /me/export`, `GET /me/export`, `GET /me/export/{id}/download`, and `DELETE /me/export/{id}`. Machine credentials cannot use them. An account can have one requested or processing export. The download remains server mediated; no public bucket or presigned URL is exposed.

Before enabling it, drain every API/worker binary that can eagerly delete object bytes and prevent those binaries from restarting. Then explicitly attest:

```sh
deepref-server accounts activate-export-retention --confirm-drained all-eager-deleting-binaries-drained-no-restart
```

The durable default-false gate is independent of tenant-key parser activation and workflow-content cutover. An operator assertion records responsibility; it does not discover deployment readiness. Hosting remains undecided. This feature uses no external billing or AI provider calls.

A repeatable-read snapshot selects active-owner workspaces, including co-owned workspaces, and explicit relational fields. The ZIP contains JSON sections for profile, workspaces, memberships, projects, protocols/criteria, records/reports/studies, screening events, document metadata, workflow file metadata and typed local billing projections. Original document objects and both object-backed and legacy inline workflow bytes are included. Filenames remain metadata; archive paths use UUIDs. Every source length and SHA-256 must match before publication.

Exports currently declare **partial scientific coverage** in `manifest.json` and in the status response's `scope_manifest`. Version 2 adds parsed document pages/blocks, study relationships/history, acquisition runs/items, appraisal assessments/evidence/history, extraction fields/values with supersession and verification history, scientific AI proposals/evidence, and review automation output/artifacts/lineage. Reconstructable embeddings/graph caches, prepared model requests, execution errors, and workflow node input/output or trigger bodies remain excluded. Also excluded are session cookies/tokens, WorkOS identity IDs, API-key secrets/verifiers, raw connector/provider payloads, administrative/security audit, internal financial retention notes, workflow secrets/configuration and non-owned workspaces. A completed job means its declared inventory was fully verified and packaged; it does not mean every product table was exported. Missing or corrupt files fail the export rather than silently shrinking the inventory.

Limits are account-wide per attempt: 50 owned workspaces, 20,000 relational rows, 2,000 source files, 1 MiB encoded JSON per row, 32 MiB total JSON, 512 MiB source bytes, and a ten-minute generation deadline shared by collection, packaging and publication. The archive ceiling adds the JSON allowance and 4 MiB ZIP overhead. The configured object-store upload limit can be lower and fails closed. A dedicated blocking task owns private staging and polls the generation future; synchronous collector/ZIP writes, finish and final rehash never occupy an executor worker. Deadline and cancellation checks run between bounded operations and each rehash chunk; caller waiting and publication share the absolute deadline. An already dispatched adapter operation remains owned and polled until it stops, even after the caller returns a timeout. Kernel filesystem calls cannot be preempted. Scope and the actual private directory are journaled before scientific writes, and staging removal precedes the writer's durable stopped acknowledgement. Process termination or failed cleanup remains a visible pending obligation; elapsed time does not acknowledge it.

Each worker reserves one additional PostgreSQL connection for job lifecycle operations and its liveness heartbeat, separate from the configured business pool. Budget **DATABASE_POOL_MAX + 1** connections per worker (plus the API's own pool) when sizing PostgreSQL. The control pool has a fixed maximum of one and is checked at startup. Holding the sole business connection through an export upload therefore does not prevent the actual worker lease-renewal schedule from progressing.

Artifacts and sources are retained for seven days from snapshot collection. Download authorization rechecks active account and the captured ownership set; revocation blocks subsequent downloads and releases retention. One absolute five-minute response deadline starts before authorization and is capped by retained_until after authorization; object acquisition, audit and body polling share it. Authorization requires at least five minutes of remaining retention, and delayed preparation never resets the response budget. Cancellation, failure, expiry and account completion serialize the export row and atomically release retained references. Registry retirement is permanent. Fresh durable job claims use fresh attempt UUIDs and storage keys; expired claims cannot publish.

The worker maintenance scheduler closes expired artifacts and abandoned exports whose jobs are terminal. Unknown old workers leave the new job kind in `capability_wait` and continue ordinary queued work. No backward parser/deleter safety is inferred from a heartbeat.

The additive [account-erasure workflow](account-erasure.md) keeps the full 30-day cancellation window and makes due privacy objects immediately eligible after cancellation/reference removal, without adding the operational 24-hour grace. Requests remain physically pending until actual storage and writer acknowledgements. Activation, interrupted writers and unknown uploads have explicit limits; this is not a scheduling guarantee, legal equivalence claim or full handoff acceptance.

Run the focused disposable PostgreSQL/filesystem checks with `bash scripts/verify-account-export.sh`. It takes the shared build lock, refreshes all Rust source timestamps, uses a pinned private PostgreSQL fixture with durability enabled and the existing parallel test limits, reports settings/database inventory/disk usage, and removes only its own fixture before releasing the lock. Do not point these tests at a development or production database.
