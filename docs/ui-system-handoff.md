# Deepref UI design handoff

This pass works inside Agent A’s extracted package. It retains Svelte, Tailwind, bits-ui, Storybook, public subpath exports and application ownership. The working tree already contained the package migration and substantial application presentation changes; those are preserved, not claimed as new work here.

## 1. Systemic problems found

The rendered system mixed paper/teal application styling with purple, dark-only canvas controls. Control fills, disabled states, focus rings and status tints varied between primitives. Global pattern selectors overrode component variants. Cards carried unnecessary rings/shadows, long Select labels escaped their triggers, and narrow headers and Alert actions collided. Story fixtures hid these boundaries; several were incompatible with their component types. Application graph colors silently became black because Sigma could not parse OKLCH.

## 2. Token architecture: before → after

An inherited collection of theme values, duplicated spacing and component overrides → a small private foundation palette, explicit light/dark semantic roles, and Tailwind mappings consumed by primitives.

The visual direction remains warm paper and charcoal with restrained teal actions. IBM Plex Sans serves controls and metadata; Source Serif 4 serves reading. Added distinct subtle/ordinary/strong boundaries, editable-control borders, recessed surfaces, secondary text, primary hover/active, selection, neutral interaction and related status foreground/surface/border roles. Chart colors remain separate from status meaning. Both themes have independent surface and contrast choices.

Control height is 36px, with smaller existing variants for dense composition. Spacing derives from Tailwind’s four-pixel foundation, with control/section/page roles. Corners are compact. Elevation is reserved for overlays. Motion has 120/180/220ms roles and reduced-motion handling. Keyboard focus uses an opaque two-pixel outline.

## 3. Removed or consolidated

- Removed redundant `--space-1` through `--space-8` and duplicate motion easing; replaced the provisional slow duration with the panel role.
- Removed redundant physical style entry files. The public `@deepref/ui/theme.css` export remains an alias of the canonical stylesheet to preserve the package contract.
- Removed unlayered global PageHeader, PageToolbar, Surface, MetricTile and StatePanel overrides.
- Moved application-only `.workspace-page` and `.workflow-section` compatibility styling to the application stylesheet.
- Consolidated primitive focus styling and replaced raw status/palette values throughout WorkflowCanvas with semantic roles.

## 4. Major primitive improvements

Buttons share action hierarchy, hover/pressed feedback and disabled-anchor styling. Inputs, Textarea, Select and InputGroup share control surfaces and focus. Select labels truncate inside their available width. Badge and Alert now share success/warning/danger/info treatment, including wrapping labels. Alert actions occupy normal layout flow, eliminating title overlap.

Cards use restrained boundaries. Tables distinguish selection from hover and retain accessible horizontal scrolling. Dialog, Sheet and Drawer content respects viewport height; long footer actions remain reachable. Command’s accessible title and description now live inside its dialog. Sidebar exposes its mobile close control. Window content no longer forces an empty 16:9 region. Supporting controls received focus, naming and state fixes.

## 5. Generic patterns

PageHeader wraps long titles and multiple actions. PageToolbar wraps its control groups. Surface has distinct plain, default, subtle, inset and raised roles. MetricTile uses compact tabular values and restrained status accents. StatePanel relates its icon, title and supporting copy without a decorative dashed card. LoadingButton preserves its name, prevents repeat activation and exposes busy state. WorkflowCanvas styles are scoped to its own root, follow both themes, and expose a usable narrow-screen pan/zoom hint.

## 6. Storybook organization: before → after

Inherited isolated showcases and application-shaped fixtures → **Foundations / Primitives / Patterns** with a global light/dark toolbar, accessibility addon and selective interaction stories. Stories now participate in Svelte/type checking instead of being excluded.

See [the package guide](../packages/ui/README.md) for token roles, composition conventions and commands.

## 7. Stories replaced

Rebuilt token, button, form, badge/status, table, overlay and workflow showcases. Removed superseded Surface, Containers, ProjectWorkspace and ScreeningDesk stories and their obsolete showcase components. Generic page composition replaces application-shaped package examples. Added navigation, supporting controls, responsive shell and sequence galleries. StatePanel stories use the actual `state` contract rather than an unsupported `tone` property.

## 8. Important boundaries covered

Long titles, long Select labels, multiline validation, long status labels, Alert actions, many wrapping actions, disabled links/forms, loading buttons, selected dense rows, empty table filtering, short-height dialogs, modal focus return, menu keyboard selection, command search, tabs, numeric controls, tag suggestions, Stepper current-step semantics and a mobile sidebar/modal. Fixtures are local, domain-neutral data.

## 9. Application surfaces inspected

Rendered application routes with deterministic browser fixtures at desktop and 390px widths in light and dark: project overview, settings, protocol, imports, article table/cards, deduplication, title/abstract screening, full-text screening, studies, appraisal, extraction, PRISMA, citation graph with article inspector, recommendations, automations, automation editor and assistant. Inspections include disabled forms, empty study/extraction states, inspector metadata/code, dialog content and status feedback. Settings loading and actionable error states were also inspected in both themes at 390px.

Localized application fixes: settings theme control; semantic deduplication badge; assistant surfaces/status text; keyboard-accessible protocol amendment button; wrapping overview tabs/status and assistant graph legend; RGB conversion at the Sigma boundary; white document surface for exported PRISMA ink. No feature moved into the UI package.

## 10. Accessibility improvements

TagsInput remove controls now have names; invalid ARIA selection was removed; the input references suggestions only while mounted; Escape closes suggestions while retaining focus. Stepper announces the current step instead of applying invalid selection/orientation attributes. ScrollArea’s viewport is keyboard reachable. DataTable pagination names its page-size control. LoadingButton announces busy state without adding a duplicate spinner name. Form labels/error associations are represented in stories. Status contrast was corrected, including the info role discovered just below 4.5:1. Terminal typing respects reduced motion. Dialog/menu/command/sidebar keyboard contracts are exercised in the browser.

## 11. Visual regression strategy

Added 32 component baselines: foundations, actions, validation form, status, dense table, page composition, open dialog and workflow canvas across four theme/viewport projects. Captures were inspected before acceptance; Alert-action baselines were recaptured after correcting overlap, and the canvas baselines cover constrained graph framing and the narrow-screen hint. Refreshed the 38 existing application screenshot targets after light/dark review, then re-reviewed the Studies target after restoring its visible create action and accepted four updated theme/viewport baselines. Application coverage remains in its existing suite. Application baselines include inherited migration/layout drift as well as this pass’s styling changes; they must not be interpreted as a diff attributable solely to this pass.

## 13. Remaining design debt and limits

- Some application-owned review screens still use nested evidence surfaces and bespoke spacing where audit context benefits from a bounded reading region. Study management now uses plain sections and separators for its outer composition; the remaining nested surfaces are feature-level evidence or proposal content, not package-level card defaults. Domain information architecture remains application-owned.
- WorkflowCanvas remains a spatial editor on narrow screens. Initial and control-driven fit now share explicit 50–110% bounds; interactive zoom and its slider share a separate 50–200% range. The controls derive their displayed zoom from the live viewport, including wheel and trackpad pinch changes, and disable JavaScript viewport animation when reduced motion is requested. The canvas exposes both a visible mobile hint and an always-available accessible description. Pan and zoom are still required to inspect a large graph; nodes are not converted into a separate mobile form. Canvas metadata remains deliberately dense.
- PRISMA visual fixtures now include representative identification, screening, retrieval, assessment and inclusion boxes with counts and arrows, plus the export controls. They do not cover every production-generated diagram. Exported diagrams retain their own ink colors on a white document surface.
- Automated axe results cover detectable issues in rendered fixtures, not a full manual screen-reader certification. No broad redundant axe suite was added to the UI package.
- Storybook's inherited direct-`eval` warning and large generated chunks remain in the static build output; both originate in Storybook/Rolldown's dependency graph. No dependency-stack upgrade or warning suppression was performed.
- The public `theme.css` alias is retained intentionally for compatibility. Application-specific layout compatibility rules remain application-owned.

## Follow-up verification: canvas controls

Independent review found three gaps in the previous pass: wheel/pinch zoom left the controls stale, JavaScript viewport animations ignored reduced motion, and the Fit button omitted the initial fit bounds. Two Luna agents implemented the fixes and focused browser regressions; the parent reviewed both changes. Review also corrected an intermediate implementation that conflated the 110% fit cap with the 200% interactive zoom maximum.

The viewport is now the source of truth for zoom controls. Shared internal constants define fit bounds of 50–110% and interactive bounds of 50–200%, without changing the public component API. Reduced-motion preferences apply to button and slider viewport transitions, including preference changes while mounted.

The parent inspected light/dark renders at 390px and 1100px. Wheel zoom matched the viewport, slider, and label in all four cases; a separate browser probe verified an immediate slider transition after changing the reduced-motion preference. Existing canvas baselines were preserved. Regression tests cover wheel and synthetic trackpad pinch, intermediate transform changes under reduced motion, and a wide viewport that exposes incorrect fit bounds.

Both changed Svelte components passed the autofixer. The prohibited-import scan and `git diff --check` passed.
